# ADR-032: Engineering, Coding & Quality Domain SOTA Hardening

## 1. Context and Problem Statement

Following the completion of **Batch 1** (Core Architecture & Governance) and **Batch 2** (AI Agents, Loops, Resilience & MCP Tooling), **Batch 3 (Engineering, Coding & Quality)** encompasses the core implementation and software quality mechanics of the catalog.

While all 9 skills have passed structural baseline checks, deep forensic analysis in [`docs/audit/skills/COGNITIVE_DEBT_RELATIONAL_GRAPH.md`](./skills/COGNITIVE_DEBT_RELATIONAL_GRAPH.md) identified critical cognitive domain debts:
1. **`clean-code`:** Subjective code smell definitions lacking Thomas McCabe Cyclomatic Complexity algebra ($CC \le 10$) and Sonar Cognitive Complexity thresholds.
2. **`code-review`, `code-review-lite`, `code-review-workflow`:** Informal review rubrics lacking Google Engineering Practices standards, structured severity taxonomy (P1 Blocker / P2 Major / P3 Polish), and multi-round consensus state machines.
3. **`refactoring`:** Missing Martin Fowler's formal transformation catalogs, Strangler Fig patterns, and Branch by Abstraction risk formulas.
4. **`systematic-debugging`:** 4-phase investigation described qualitatively without the Scientific Debugging Method, Git Bisect search algebra ($O(\log N)$), and RCA 5-Whys trees.
5. **`test-driven-development`, `testing-mastery`:** Missing Kent Beck RED-GREEN-REFACTOR invariant equations, Mutation Testing score calculations ($MS \ge 0.85$), and Mike Cohn Test Pyramid distribution models ($70/20/10$).
6. **`implementation`:** Lacks Atomic Change Transaction protocol and direct handoff gates with `adr-archive`.

## 2. Decision Drivers

- **Zero-Guesswork Engineering:** Mathematical bounds for complexity ($CC \le 10$), test pyramid ratios ($70/20/10$), and mutation test quality ($MS \ge 0.85$).
- **Scientific Rigor in Debugging:** Strict hypothesis testing and deterministic bisection before touching production code.
- **Score Elevation Target:** Elevate all 9 skills in Batch 3 to **Grade B+ / A / S (Target Catalog Average > 85.0)**.
- **Strict Adherence to SDLC Governance:** Full synchronization between `implementation`, `adr-generator`, and `adr-archive`.

## 3. Considered Options

- **Option A (Textual Polish):** Add simple paragraphs on testing and code review. (Rejected: Fails domain SOTA rigor).
- **Option B (Full Algorithmic Hardening — Quadra Tier II):** Formulate mathematical complexity metrics, Test Pyramid distribution algebra, Scientific Debugging trees, and Atomic Change protocols across all 9 skills. (Accepted).

## 4. Decision Outcome

**Chosen Option:** Option B. Formulate and implement the complete Quadra Decision Set (ADR-032, ADR-032-BP, ADR-032-PI, ADR-032-TODO) for Batch 3.

### 4.1 Positive Consequences
- Deterministic code complexity gates preventing unmaintainable code.
- Scientific debugging workflow eliminating shotgun debugging anti-patterns.
- Formalized Test Pyramid and Mutation Testing standards for resilient test suites.
- Production-grade code review taxonomy matching Google Engineering Practices.

### 4.2 Negative Consequences / Trade-offs
- Stricter requirements on code changes (must include tests satisfying pyramid ratios).
