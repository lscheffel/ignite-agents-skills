# ADR-035: Product, Content & Document Processing Domain SOTA Hardening

## 1. Context and Problem Statement

Following the consolidation of Batches 1 to 5 (ADR-030 to ADR-034), **Batch 6 (Product, Content & Document Processing)** governs product requirements specifications, automated evaluations, communications, and binary document transformations (DOCX, PDF, XLSX).

Forensic analysis in [`COGNITIVE_DEBT_RELATIONAL_GRAPH.md`](./skills/COGNITIVE_DEBT_RELATIONAL_GRAPH.md) identified specific domain debts:
1. **`product-spec-engineering`:** PRD specifications lack formal BDD Gherkin syntax (Given-When-Then), Kano Model feature classification, and INVEST story criteria.
2. **`prompt-engineering`:** Qualitative guidelines lacking Chain-of-Density (CoD), DSPy declarative optimization, Few-Shot exemplars, and System/User boundary protection.
3. **`llm-as-judge`:** Evaluation rubrics lack statistical inter-annotator agreement math (Cohen's Kappa $\kappa \ge 0.70$), position bias calibration, and G-Eval criteria.
4. **`content-creator`:** Copywriting advice lacks empirical readability formulas (Flesch Reading Ease $RE \ge 60$) and conversion algebra.
5. **`content-research-writer`:** Academic citations lack formal APA 7th edition schemas and CRAAP source credibility scoring.
6. **`email-composer`:** Lacks executive BLUF (Bottom Line Up Front) communication hierarchy and subject line open-rate geometry ($N_{\text{chars}} \le 50$).
7. **`docx-processing`:** Template mail-merges lack python-docx / docxtpl schema validation and OOXML style inheritance rules.
8. **`pdf-processing`:** Extraction logic lacks PDF/A archival compliance, vector table extraction algorithms (PDF Plumber spatial analysis), and OCR fallback ladders.
9. **`xlsx-processing`:** Large dataset processing lacks OpenPyXL streaming memory bounds (`read_only=True` for $>10,000$ rows) and formula AST parsing.
10. **`changelog-generator`:** Commit parsing lacks strict Keep a Changelog (v1.1.0) compliance and Conventional Commits 1.0.0 SemVer bump trees.

## 2. Decision Drivers

- **Empirical Evaluation & Readability:** Mathematical bounds for LLM judgment ($\kappa \ge 0.70$), Flesch readability ($RE \ge 60$), and Gherkin BDD verification.
- **Industrial Document Processing:** Memory-bounded OpenPyXL streaming, PDF/A compliance, and OOXML schema isolation.
- **Target Grade:** Elevate all 10 skills in Batch 6 to **Grade B+ / A / S (Target Catalog Average > 86.0)**.

## 3. Considered Options

- **Option A (Informal Prose):** Descriptive guidance for writing and parsing. (Rejected).
- **Option B (Formal Mathematical Models & Document Engine Schemas — Quadra Tier II):** Ingest Cohen's Kappa, Flesch Reading Ease, OpenPyXL chunk streaming, Gherkin BDD, and Keep a Changelog v1.1.0 standards. (Accepted).

## 4. Decision Outcome

**Chosen Option:** Option B. Formulate and implement the complete Quadra Decision Set (ADR-035, ADR-035-BP, ADR-035-PI, ADR-035-TODO) for Batch 6.

### 4.1 Positive Consequences
- Statistically sound LLM evaluation with position bias mitigation.
- Memory-safe binary document processing preventing OOM crashes on large files.
- Enterprise-grade product specifications with automated testable Gherkin acceptance criteria.
- Standardized changelogs conforming to SemVer 2.0.0 and Keep a Changelog.

### 4.2 Negative Consequences / Trade-offs
- Large Excel/PDF processing requires streaming pipelines rather than loading entire files into memory.
