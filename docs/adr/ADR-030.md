# ADR-030: Core Architecture & Governance Domain SOTA Hardening

## 1. Context and Problem Statement

Following the completion of **Etapa 1** (ADR-027, ADR-028, ADR-029), all 60 skills in the repository received standardized structural ergonomics, bilingual triggers, Mermaid decision graphs, and scaffolding. While this eliminated structural failures (raising Catalog Mean Score to `84.0/100`), the **Batch 1 (Core Architecture & Governance)** skills still exhibited substantial domain-level cognitive debts identified in [`docs/audit/skills/COGNITIVE_DEBT_RELATIONAL_GRAPH.md`](./skills/COGNITIVE_DEBT_RELATIONAL_GRAPH.md):

1. **`adr-architecture-elevation` & `adr-generator`:** Subjective tiering lacking mathematical reversibility algebra and blast radius coefficients.
2. **`adr-archive`:** Evidence Records lacking cryptographic commit hash binding and soft tombstoning.
3. **`architecture-review`:** Architectural reviews lacking quantitative fitness functions (Martin's Distance $D = |A + I - 1|$).
4. **`governance` & `agents-md-management`:** Governance instructions documented purely textually without machine-readable Governance-as-Code schema contracts.
5. **`cap`:** Context acquisition saturation determined empirically without dynamic token allocation formulas.
6. **`brainstorming`:** Ideation transitions lacking quantitative Double Diamond ambiguity reduction gates.

## 2. Decision Drivers

- **Zero Cognitive Ambiguity:** Every decision and triage step must provide deterministic mathematical or algorithmic criteria.
- **SOTA Industry Parity:** Incorporate principles from Two-Way Door Decision Theory, Architecture Fitness Functions (Building Evolutionary Architectures), and Governance-as-Code.
- **Score Elevation Target:** Elevate all 8 skills in Batch 1 to **Grade S / Diamond (Score $\ge$ 96.0/100)**.
- **Traceability:** Maintain bidirectional linkages between Decision Sets, Evidence Records, and Code.

## 3. Considered Options

- **Option A (Superficial Tweaks):** Add brief explanatory paragraphs without formal formulas or schemas. (Rejected: Fails domain SOTA rigor).
- **Option B (Full Algorithmic Hardening — Quadra Tier II):** Formulate mathematical equations, concrete schema contracts, cryptographic hash gates, and Double Diamond metrics across all 8 skills. (Accepted).

## 4. Decision Outcome

**Chosen Option:** Option B. Formulate and implement the complete Quadra Decision Set (ADR-030, ADR-030-BP, ADR-030-PI, ADR-030-TODO) to inject domain-specific SOTA engineering into the 8 core architecture skills.

### 4.1 Positive Consequences
- Deterministic decision triage based on calculated Blast Radius ($BR \ge 7.0$).
- Cryptographically verifiable Evidence Records linking `git rev-parse HEAD` directly to ADR closures.
- Automated architectural fitness functions detecting coupling and cycle violations.
- Formal Governance-as-Code JSON policies consumable by AI agents.
- Batch 1 Mean Score elevated to $>96.0/100$ (Grade S).

### 4.2 Negative Consequences / Trade-offs
- Higher cognitive density in skill definitions, requiring agents to strictly evaluate formulas.
