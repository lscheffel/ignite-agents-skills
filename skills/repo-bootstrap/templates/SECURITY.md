# Security Policy & Vulnerability Disclosure

## 1. Supported Versions
We actively maintain and provide security patches for the following release tracks:

| Version Branch | Status | Maintenance Level |
|:---|:---|:---|
| **v3.x** | :white_check_mark: Active | High Priority / Hotfixes |
| **v2.x** | :warning: Maintenance | Critical Security Only |
| **< v2.0** | :x: End-of-Life | Unsupported |

---

## 2. Reporting a Vulnerability
We take the security of our software seriously. If you discover a security vulnerability, please do not open a public issue. Instead, follow these steps:

1. **Email Contact:** Send a detailed report to `security@example.com` (or project maintainer).
2. **Report Contents:**
   - Detailed description of the vulnerability and attack vector.
   - Proof of Concept (PoC) or minimal reproducible example.
   - Potential impact on system confidentiality, integrity, or availability.
   - Affected components, files, or endpoints.

---

## 3. Response SLA & Remediation Protocol
- **Initial Acknowledgment:** The security team will acknowledge receipt within 24 hours.
- **Triage & Assessment:** Preliminary triage and severity classification (CVSS v3.1) within 72 hours.
- **Patch Release:** Emergency hotfix release issued within 7 business days for high/critical vulnerabilities.
- **Coordinated Disclosure:** We kindly request that you wait for a patched release before publicly disclosing any technical details.
