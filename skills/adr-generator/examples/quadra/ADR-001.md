# ADR-001: JWT Authentication Standard

## Status
Accepted

## Context
The system requires stateless user authentication to scale horizontally.

## Decision
Adopt JWT (JSON Web Tokens) with ECDSA for signature, with short-lived access tokens (15 minutes) and rotating Refresh Tokens stored in HTTP-Only Cookies.

## Considered Alternatives

### Alternative A: Server-Side Sessions (Redis)
- **Pros**: Immediate session revocation, total control over the lifecycle.
- **Cons**: Requires shared state between instances — hinders simple horizontal scaling.

### Alternative B: JWT with HS256 (Symmetric Key)
- **Pros**: Easier to implement, no key pair required.
- **Cons**: The same key signs and validates — any service that validates can also forge tokens.

### Alternative C: JWT with ECDSA (Chosen)
- **Pros**: Asymmetric signature — services can validate without being able to forge; stateless; horizontally scalable without shared state.
- **Cons**: Greater learning curve than HS256; requires key pair management.

## Consequences
### Positive
- Ease of scaling (stateless).
- Security against XSS (http-only cookies).
### Negative
- Difficulty in invalidating tokens before expiration.
